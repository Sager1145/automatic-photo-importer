# UI style and layout audit — 2026-10-29

Scope: the integrated `main` after merging every outstanding branch, which adds the **Library browser** (file viewer and catalog). Pages covered: Import › Media and Files & folders, Library browser, Library tools › Organize, Duplicates and Recovery & cleanup, Activity › Queue, History and Issues, and Settings. The app ran from its QA fixtures (`--qa`, plus the EXIF-tagged browser fixtures) and was driven through the DevTools protocol at 1440×940 and 1000×700, at the default 125% text size. Every button and field was measured for height, radius and font size. Screenshots: [ui-audit-evidence-2026-10-29](ui-audit-evidence-2026-10-29/).

The questions asked:

1. Is the visual style consistent?
2. Is the layout easy to use, with no element taking a disproportionate amount of space?
3. Can element heights be unified?
4. Is every tab, element and button in the right place and group, following the user's workflow?

## Findings and changes

### Consistency: one control size (fixed)

- Four container rules overrode `--control-height` with fluid `clamp(… cqi …)` values, so standard buttons measured 40, 41, 42 or 45 px depending on where they sat. They are removed. Every standard control is now 2.5rem (41 px at 125%), and narrow containers collapse labels to icons instead of shrinking controls.
- A new compact token, `--control-height-sm` (2rem), replaces three one-off small sizes: the overview collapse button (1.75rem), the sidebar Sources refresh button (1.6rem) and the sidebar row icon buttons. The sidebar eject and reveal buttons were full 41 px circles, which wrapped source names such as "Fixture card / 1".
- The **Library browser** had its own sizing system: hard-coded 44 px fields and buttons, small field radii, and rectangular palette buttons. It now uses the app tokens. Fields are `--control-height` with `--radius-md`, palette blocks and presets are capsules at `--control-height-sm`, and the remaining 44 px rules (12 of 13; the last is a content max-height) use the tokens.

### Consistency: one primary action per screen (fixed)

Coral primary buttons competed with the title bar's **Start all selected**:

- Every source card's **Import / Back up** button. With six sources, that made six coral buttons, plus a coral ring around every card.
- **Check folder layout** in the destination strip and in Library tools, where it also competed with **Organize now**.

The card start and both checks are now secondary buttons. An included card keeps a tinted border (`--accent-border`); the checkbox remains the inclusion control.

### Layout: the Library browser hid its content (fixed)

At 1440×940 the first file column started at y≈735. Above it sat the always-open hierarchy editor (palette, insert position, path blocks, block inspector) and the sort and width row. Changes:

- The hierarchy editor starts collapsed. Its summary shows the current path (for example *Date › Camera › Format › Files*), so the structure stays visible. The columns now start at y≈450.
- The page repeated its title ("Library browser" in the title bar and again as an in-page heading). The in-page heading is now visually hidden but kept for assistive technology, matching the other pages.

### Placement: browser presets were global (fixed)

**Browser presets** sat in the sidebar on every page, between navigation and Sources. It pushed the source list down on Import, Library tools and Activity, where presets mean nothing, and its full-width rows failed the `rules-sweep` check 2,576 times. Presets now live on the Library browser page, directly above the hierarchy they configure, as chips sized to their names.

### Correctness in the browser preview (fixed)

The preview showed raw values ("0.008 s"), while the columns and the documentation use photographic labels ("1/125 s"). The preview now uses the same formatter as the columns for shutter speed, aperture and focal length. A test covers it.

### Import (fixed)

- **Contradiction in empty modes:** Media mode said *"Connect camera storage or a memory card"* and *"0 connected"*, while the overview said *6 connected sources* and the sidebar listed six. They were folder sources, which belong to Files & folders. The empty state now says *"6 connected sources are in Files & folders."* with a button that switches mode (and the reverse). It has singular forms and all four languages. The empty state's padding dropped from 2.75rem to 1.75rem.

### Activity (fixed)

A disabled **Stop all** sat alone on one row, with *"No jobs yet."* on a full-width row below it. They now share one row.

### Title bar position (fixed)

Pages that scroll reserved a 12 px scrollbar track and short pages did not, so the title bar's controls shifted horizontally between pages (All errors' right edge at 1412 px versus 1424 px). `scrollbar-gutter: stable` has no effect on the viewport in this Chromium build, so the root uses `overflow-y: scroll`.

### Content hidden under the title bar (fixed)

When something was scrolled into view from below (keyboard focus moving up, or a `scrollIntoView` call), it stopped at y≈16, underneath the fixed title bar. The title bar is a window drag region, so the hidden control could not be clicked or dragged. The browser QA check `browser-real-library-read-only` caught this: a hierarchy palette block came to rest under the title bar, and its drag never started. The root now sets `scroll-padding-top` to the title-bar height plus a small gap, so scrolled-to content stops below it on every page.

## Second pass: recommendations implemented

The five recommendations from the first pass are now in the app.

### R1. Idle sidebar sources take three lines, with nothing hidden

Each source used four lines: name, capacity bar with step dots, free space, then a drive-activity line with its own bar. With six sources, the Destinations section sat below the fold.

- **Idle sources** (no running or queued job, not scanning, not low on space, capacity known) now use three lines. The activity figure (⚡ 19%) joins the free-space line, and the separate activity bar row is dropped. Free space, activity and step dots all stay on screen.
- **Running, scanning, low-space and unknown-capacity sources** keep the four-line layout.
- **Names in the sidebar fit:** names now count when the sidebar sizes itself, measured on one line with each line's own icon and button room (`sidebarFit` takes a per-line `chrome`, rounded up). "Fixture card 2" no longer wraps, and the sidebar grew by 3 px, within its 360 px / 28% cap.

### R2. Library browser: Sort and Column width are in the toolbar

They used to sit alone on a right-aligned row above the columns. They now sit at the end of the toolbar, after Search. The selection row, with its chips and Clear all, appears only when something is selected or filtered.

### R3. Library browser: one focus ring and a visible Files column

- **Focus:** a focused list drew two coral rings, one around the list and one around the active row. The list's ring is now dropped while it has rows, and the active row keeps its high-contrast ring.
- **Files column:** when a file opens in the preview, the column strip scrolls so the Files column, the last one, is fully visible beside the preview. Names are no longer cut off at the preview's edge.

### R4. Overview metric cells line up

Each helper note reserves two lines, so the metric cells line up. Longer notes still show in full, never clipped, and each note is also its own tooltip.

### R5. Organize: the destination selector names drives

The options read *"A006 › photobackup"* instead of a raw absolute path. The selector uses the app's chevron select and spans the card's width. The chosen path appears beneath it on one line, cut at the start so its end stays visible.

## Settings: grouped by where, how, then when

The eight categories themselves were sound. The problems were in the rows inside them:

| Was | Now | Why |
| --- | --- | --- |
| **Backup folder** name under Storage; **Video backup folder** inside Folders › Folder structure | Both in a new **Folders › Backup folders** section, first in Folders | The two folder names belong together, and both decide how files are laid out, not which drive they go to. Storage now holds only the destinations and the copy policy. |
| **Drive backups** (Additive or Mirror) under Storage | **Importing › Drive backups**, after Copying | It decides what a Files & folders import does, not where it goes. The Import page's *Change* button now opens Importing. |
| Importing: Starting imports → Ejecting drives → Delete originals → Copying | Starting imports → Copying → Drive backups → **After an import** (Delete originals, then Ejecting drives) | This follows an import from start to finish. Eject happens after Delete originals, as its own description says, and both keep their titles as subheadings. |
| Performance › a section also titled "Performance" | **CPU and memory** | It is no longer a duplicate of its category name. |

Lock behavior is unchanged: the settings that were locked during work still are, and the rest stay usable.

### Independent review

An independent review accepted the change with fixes. These were applied:

- **Rounding:** the sidebar width now rounds up, so fractional widths never leave a name a fraction of a pixel short. A test covers it.
- **Catalog lookup order:** the companion lookup tries the live primary first, then its moved row, and the missing row only last.
- **Notes stay visible:** an idle source whose capacity is unknown or shared keeps its visible note ("Same drive as …", "Capacity unavailable over USB"). A test covers it.
- **Name measurement:** names are measured in two layout passes in total, not two per drive.
- **Focus ring:** the list's focus ring is dropped only while the active row is on screen.
- **Duplicate labels:** two destinations that would read the same show their full paths. A test covers it.
- **Parallel-limit tooltip:** it now includes the note's full text.

Known and left as is:

- **Placeholder count:** while recovery-file deletion finds the folders to check (a few seconds on a very slow drive), it reports a placeholder count (0 of 0) rather than a moving one.
- **Destination names:** they also count toward the sidebar width, so a long destination name doesn't wrap either.
