# Photo Importer: consolidated UI audit — 2026-10-23

This report combines the navigation/functionality audit with the completed Electron animation, layering, timing, visual-consistency, spacing and readability audit. It is intended for product and implementation planning.

**Recommendation (revised after validation, see [Decisions](#decisions-after-validation)):** three task tabs—**Import** (with a **Media / Files & folders** mode), **Library tools**, **Activity**—with **Settings anchored below them**. The original proposal had a separate Backups tab; backup now becomes a mode inside Import because it shares Import's sources, destinations, queue and job cards. Preserve the verified interaction and visual fixes when reorganizing the workflows.

## Validation against the code

Checked on 2026-10-23 against the working tree (`main` at `f649710` plus the uncommitted animation/visual fixes). `npm run typecheck` passed and `desktop/tests/motion.test.ts` passed 6/6. The other runtime numbers in this report were not re-run.

**Confirmed:** the six pages (`RootApp.tsx:413`); ReviewPanel renders over any page (`:421`); the titlebar controls; Pause pauses only import jobs while titlebar Stop discards the review, aborts scans and stops every job (`main.ts:1124`, `:1159`); Drives repeats source selection and the remembered/ignored lists; Organization repeats Review/Organize in the titlebar and the card; the folder-source gate appears twice and defaults off (`preferences.ts:10`); the missing-metadata Continue calls `applyReview`; History is titled "Import history" and `HistoryEntry` is `{id,date,title,detail}`; duplicate removal is an accent primary button; Levels 2 and 3 resolve identically (`duplicate-rules.ts:107`); duplicate removal sets files aside into recovery; in-place organizing is rejected under the default `video-root` layout (`main.ts:814`); organize options reset each run; Mirror plus Fill-first is blocked in both the backend (`main.ts:644`) and the UI; source-original deletion re-verifies source and backup checksums (`core/originals.ts:62`); no scoped bulk Stop exists.

**Corrections:**

- The destination "warning" that starts organization is a quiet Organize button in the destination slot that dispatches `organizeBackup`. The fix is the same; the wording above is corrected.
- Manual Clean up removes resumable, kept and unbound items. Recoverable copies are kept by both paths.
- Pause skips organization jobs unless a source id is given, so "Pause imports" is the accurate label. Stop is the only bulk action that reaches organization.
- Level 3's description promises confirmed EXIF removal. That behavior doesn't exist, so the description is wrong, not just old.
- The "Organize instead (move, no extra space)" button in the same-drive notice also dispatches `organizeFolder`, so it hits the same video-root rejection.
- `styles.css` says "Start keeps its label", but the 36rem container rule collapses Start to an icon.

**Missing from the inventory:** the sidebar Sources and Destinations panels (with their own error badges), the page-independent error toast, BackupCheck and Organization recovery on the Organization page, and the non-macOS window controls. The proposal should give each of these a home.

## Navigation and workflow findings


1. **Import desk carries too many unrelated jobs.** Media import, arbitrary file backup, organization progress, source selection, destination monitoring, and performance configuration share one page. Copying media into a library, preserving a folder tree, and moving existing files deserve distinct task contexts.
2. **Drives duplicates existing controls.** Its connected-drive selection already exists on import cards. Its remembered/ignored lists are also rendered in Settings. It does not need a separate primary destination in the proposed structure.
3. **Organization mixes three scopes.** Organizing a destination, organizing a chosen folder in place, and repairing only the configured photo/video library roots are different operations. The current buttons do not make those scope differences prominent enough.
4. **Setup, execution, and recovery compete visually.** Organization repeats Review/Organize in the title bar and content card, while another prominent Organize backup action sits beside them. Recovery controls occupy a large adjacent column. The selected-folder scope appears below the execution buttons.
5. **Preferences are scattered and repeated.** Automatic import, concurrency, folder-source availability, overview visibility, and backup-folder automation appear in multiple locations. Settings → Importing also contains resource limits, arbitrary-file backup policy, metadata exceptions, and extension routing.
6. **History is narrower in name than in content and weaker in actions than recovery.** Its records include more than imports, but the screen says Import history. It displays text records while recovery and issue resolution live elsewhere.
7. **A review floats above any destination.** RootApp renders ReviewPanel before the selected page, so an import or organization review can appear above Settings or History. The operation loses its visual ownership.

## Proposed navigation

### Import

Only media entering the library: cameras, cards, media folders, selection, scan, review, copy, and verification. Put Add folder in the source header, so it is discoverable even with nothing connected. Keep a concise destination summary visible before starting. Show detailed inventory and disk activity on demand.

Current import jobs stay here, but organization and duplicate-removal jobs should not become import cards. A compact cross-workspace activity indicator can link to Activity.

### Import → Files & folders mode

Give arbitrary-file backup a clear workflow: choose drives/folders → see destinations → confirm Additive/Mirror → review if needed → run. This is a file/folder copy, not a disk-image or operating-system backup; use copy that makes that scope clear.

Mirror must remain visible for each run because it changes what happens to files already in the backup. Destination replication policy is a separate concept: “Copy to both destinations” does not mean “Mirror source changes.” Preserve the current incompatibility between Mirror and “Fill first, then second.”

This mode reuses Import's sources, destinations, queue, transfer engine and job controls; it does not need a separate scheduler. It was chosen over a dedicated Backups tab because a separate tab would repeat the source list and the job area.

### Library tools

Two peer subtabs: **Organize** and **Duplicates**. This is a toolbox for existing files; it does not imply building a photo browser.

Organize starts with an explicit scope choice: configured library roots, selected folders on a destination, or a folder in place. Then show source and target paths, folder-rule preview, current-run options, and Review changes. Preserve each existing scope's behavior rather than silently mapping all three to the same backend action.

Duplicates keeps scope, evidence, keeper decisions, removal policy, and impact summary together. Link to recovery after removal instead of appending the entire recovery history below the groups.

### Activity

Jobs, History, Issues, and Recovery combine the current fragmented monitoring and aftercare. Use badges for jobs needing attention or recoverable operations. Keep contextual job controls in the workspace too, so routine use does not force a tab switch.

History should distinguish Import, Backup, Organization, Duplicate removal, and Cleanup. Durable drill-down or retry links require structured operation IDs/types beyond the current small text-based HistoryEntry; do not fabricate links for records that cannot support them.

### Settings

Anchor Settings at the bottom. Proposed categories:

- **General:** language, appearance, accent, text size.
- **Storage:** destination locations, destination count/order, copy-to-both/fill-first policy, backup root names.
- **Folder rules:** date/camera builder, format/media layout, video path/template, edited-export routing, advanced templates.
- **Import & backup defaults:** automatic import, verification/error behavior, additive/mirror default.
- **File handling:** missing metadata, unknown extensions, problem files, macOS sidecar cleanup.
- **Devices:** remembered/ignored choices and historical camera information.
- **Performance & diagnostics:** simultaneous sources, CPU/memory limits, logs and exports.

Place post-import folder checking/automatic organization with the relevant defaults, with a clear “Moves existing library files” explanation. Do not mix manual cleanup commands into that preference panel.

## UI versus Settings decisions

**Keep in the task UI:** source and target selection, current job scope, review/apply, pause/resume/stop, queue order, failed-file decisions, duplicate keeper choices, current-run organization options, Mirror impact, recovery/undo, and explicit source-original deletion. These determine the operation the person is about to perform.

**Move to Settings:** saved routing rules, destination policy defaults, resource limits, remembered devices, metadata/extension defaults, after-import automation, verification/error defaults, and appearance/language. The workspace can summarize them and deep-link to the exact category.

**Keep a quick workspace control backed by one preference:** automatic-import On/Off, list/grid, overview visibility, and optionally queue concurrency. Persistence alone is not a reason to bury a useful operational control; avoid giving every preference its own permanent toolbar button.

**Remove the “Enable media folder selection” gate:** Add folder is an explicit user action and should be directly available. Its current toggle appears in both Import and Settings, and defaults off. Removing this gate is a proposed behavior change, not merely relocating its button.

Do not turn the organization choices into saved settings without a separate decision: remove-empty-folders and release-duplicates currently reset for each run. Label that group “For this run.”

## Specific corrections exposed by the audit

1. **Duplicate Levels 2 and 3 have the same current resolution behavior.** `automatic()` accepts only SHA-identical groups for either level. Replace three levels with “Choose every keeper” and “Suggest keepers for identical files,” unless a real third behavior is deliberately designed. Before apply, “Removed automatically” should say “Keeper selected automatically” or “Will be set aside.” Scanning itself does not remove those files. The installed app's Level 3 wording is older and differs from the checkout.
2. **“Space to free” is deferred.** Duplicate removal moves files to recovery first. Show “Space recoverable after permanent release” and retain the explanation next to the removal action.
3. **Organize a folder is unavailable under separate video-root layout.** The backend rejects this combination, while that layout is the current default. Show the incompatibility before the picker or offer an explicit compatible per-run layout. Do not make users discover it through an error after selection.
4. **Manual Clean up is more consequential than its label suggests.** It also removes resumable, kept and unbound staging items that automatic cleanup retains (`core/residue.ts`, `keepResumable:!all`); only recoverable complete copies survive both paths. Put it in Recovery & maintenance, preview categories/counts/bytes, and name the consequence before applying. Preserve the separate handling of recoverable complete copies.
5. **Clear, skip, acknowledge, and verify are different outcomes.** Clearing issue display or acknowledging skipped errors must not read as a successful verified import. Use “Dismiss issue,” “Skip file and retry,” and “Mark issues reviewed” where those match the action; preserve factual counts in results/history.
6. **Keep the existing distinction between organization cleanup and Duplicate tools.** The organization option removes source copies already confirmed at their destination; Duplicate tools compare groups and choose keepers. Putting both under Library tools must not imply identical scope or a shared automatic deletion policy.
