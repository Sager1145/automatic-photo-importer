# 分类预览与 EXIF 分栏浏览：设计草案

日期：2026-10-28。状态：供用户评审；本轮只做调研与计划，不实现产品、不提交 Git。

## 目标与默认范围

在侧边栏增加「分类预览」，让用户像使用 macOS Finder 分栏视图一样浏览照片库，并通过实际目录、拍摄日期、名称、格式、相机和镜头，以及焦距、光圈、快门、ISO 查找照片。扫描、导入和整理产生的数据自动进入可持久化查询的索引；自定义目录规则与未整理提醒采用同一套落位逻辑。

**用户已确认**：第一版浏览备份目标中的照片库。推荐的细化方式：涵盖独立照片根和视频根；每次选择一个图库，不跨两份备份聚合计数。卡/USB 相机只贡献扫描数据和导入结果，不作为第一版常驻可浏览图库。后续可复用同一模型支持用户显式添加的文件夹。

数值分类、动态字段、目录适配、自动更新和提醒属于第一版完整范围，不把 EXIF 范围查询推迟到后续。照片和视频都可被列出；视频缺失摄影参数时显示「未记录」，不新增视频播放功能。

## 界面和交互

侧边栏保留导入、图库工具、活动等入口，新增「分类预览」。入口下可显示所选图库与「待整理」数量；字段列表和横向列放在主区域，避免塞满窄侧栏。点击目标磁盘可进入该目标的分类预览，整理入口继续保留明确动作。

主区域从上到下：

1. 图库选择、实际文件夹/分类浏览切换、搜索、索引状态。
2. 可调整的分类顺序，例如「相机 → 镜头 → 焦距」，以及当前筛选条件与清除操作。
3. 横向分栏；左栏选择决定右栏内容，最右端是文件与预览。
4. 状态区：结果数量、扫描覆盖率、最近检查时间、待整理提示。

示例（产品布局草图，不是原型）：

```text
侧边栏          分类预览：photobackup       [分类浏览] [实际文件夹]
分类预览        顺序：[相机] → [镜头] → [焦距]     筛选：ISO 100–800
  备份盘 A      ┌相机────────┬镜头─────────────┬焦距────────┬文件─────────┬预览──────┐
  待整理 126    │NIKON Z f › │24–70mm f/4 ›   │24–35 mm › │DSC_001.NEF │照片      │
                │SONY …     │50mm f/1.8      │35–50 mm   │DSC_002.NEF │EXIF      │
                └───────────┴────────────────┴───────────┴─────────────┴──────────┘
```

Finder 借鉴的是逐级选择、保留父级上下文、各列独立垂直滚动、整体横向滚动及末端预览。**EXIF 分类是本产品扩展**，不是 Finder 原有能力；具体来源见研究记录。

### 分栏状态规则

- 实际文件夹模式按真实目录展开；分类模式以查询结果形成虚拟层级，两者共享筛选条件与文件预览。
- 每列标题可换字段或删除；分类顺序可调整、保存为本机偏好。日期可展开年 → 月 → 日；名称提供搜索、自然排序和按首字符分组，数字归 0–9、其他归「其他」。默认不创建海量“一个文件名一个分类”的列。
- 分类列默认单选；显式多选使用勾选或 Cmd/Ctrl，多项合并为该列的 OR。跨列/跨字段为 AND；重复同一字段的条件求交集。多选时下一列显示并集的下一层结果。
- 改变左列选项会使其右侧选择失效并清空，保留分类字段顺序。单纯排序或调整列宽不改变选择。
- 类别显示当前上游约束下的数量；同一字段的多选列表使用“排除本字段条件”的候选计数，便于继续添加选项。最终文件数应用全部条件。数字范围的候选计数也采用同一规则。
- ↑/↓ 移动行，→ 进入下一列，← 返回父列，Home/End 到列首尾；Tab 到工具和预览操作。文件上 Space 打开/关闭预览，Esc 先关闭预览再清空活动列选择。所有行保留可见焦点，列使用命名 listbox、合适的多选语义，避免照搬原生控件名字。
- 列宽可拖动，记住本机偏好。默认 220 px，最小 180 px；窄窗口横向滚动并将活动列滚入视口，预览可折叠。1280/1000/800 px 与较大文字均需验收，不强行压成不可读列。
- 结果和类别均分页、列表虚拟化；不将全库条目装入 React。选中文件才读取缩略图和完整 EXIF，快速换选时忽略旧响应。

## 分类与数值语义

| 字段 | 存储/比较 | UI 与分类 |
| --- | --- | --- |
| 日期 | 保存原始拍摄字符串、时区信息与相机本地日历年/月/日 | 拍摄日期是默认；不随电脑时区改变分组。文件修改日期是独立字段 |
| 名称 | 原名及自然排序键；路径仅用于定位 | 名称排序、首字符分类、名称包含搜索；不是磁盘重命名 |
| 相机/镜头 | 保留原始显示名、去首尾空白/折叠空格/NFC/大小写归一键 | 不凭模糊字符串合并不同镜头；默认复用当前可信 LensModel，缺失则未记录 |
| 格式 | 文件扩展名归一化和现有 MediaKind；需要时存声明的文件类型 | RAW 与 NEF/ARW 等具体格式可分开筛选，不把 JPEG/RAW 当同一文件 |
| 焦距 | 实际毫米数，可查询 REAL | 35 mm 或范围 24–70 mm；35mm 等效焦距未来为独立字段，不能混合 |
| 光圈 | FNumber 的 f 数，可查询 REAL | f/1.8、f/2.8–f/5.6；不是镜头最大光圈，也不是 APEX ApertureValue |
| 快门 | ExposureTime 秒，可查询 REAL | 输入 `1/125`、`0.008s`、`2s`；以秒排序。`1/1000–1/125` → `[0.001,0.008]` |
| ISO | 有限正数；不假定所有设备都只给常规档位 | 已观测值和范围；0、NaN、无穷不成为分类 |

范围输入两端均包含；自动分桶采用左闭右开，最后一桶包含最大值，防止边界重复。用户可以切换「具体值 / 范围」、修改边界并保存。默认范围建议：焦距 <24、24–35、35–50、50–85、85–135、≥135 mm；光圈 <2、2–2.8、2.8–4、4–5.6、5.6–8、≥8；ISO <200、200–400、400–800、800–1600、1600–3200、≥3200；快门 <1/1000、1/1000–1/250、1/250–1/60、1/60–1、≥1 秒。这些是设计建议，不是用户已指定的固定分档。

“具体值”按归一后的读出数值分组，不按 UI 四舍五入串分组；若不同原值显示相同，增加显示精度。手输值匹配使用相同数值归一流程，机器浮点舍入最多允许 1e-9 相对误差，不能把标称 1/125 和另一个读出时间任意并为一组。

字段可用性基于当前图库扫描所得：显示 `knownCount / missingCount / errorCount / pendingCount` 和数值最小/最大值；类别按上游筛选实时收敛。固定支持的摄影字段即使没有值也可见但禁用并标注原因，其他可用字段由观测数据提供。第一版自动提供上述字段，**不做任意 EXIF 标签的无类型查询器**。

`未记录`（成功读取但无该字段）、`读取失败`、`尚未读取`严格分开。只用当前解析器可信值，不以文件夹名补造 EXIF，不对缺失焦距填 0，不自动从 APEX 或数字 LensID 猜真实参数。后续若添加可靠镜头推断，需保留来源并增加回归样本。

## 持久化索引与深模块

### 方案比较与选择

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 扩展现有 JSON/内存缓存 | 实现直观 | 大库反复载入、范围/组合查询和更新成本高 | 不适合作为查询主索引 |
| 在每块外置盘直接写 SQLite | 换机可携带 | 拔盘与文件系统差异增加数据库运行风险，离线不可查 | 暂不选为在线数据库 |
| 本机 SQLite + 可重建索引 | 事务、范围查询、分页；离线能看已索引信息 | 换机首次需要扫描 | 推荐第一版 |

默认位置：`app.getPath('userData')/catalog/catalog.sqlite`。WAL/SHM 只在本机应用目录。元数据缓存可重建，绝不替代复制校验、恢复日志或 SHA 索引。现有外置盘 `Photo Importer Data` 的密封记录与版本机制保持职责不变。可携带的密封元数据快照作为后续可选项；当前不维护两份活动数据库。

使用独立 utility process 拥有单个 SQLite 连接并串行写入；同步的 `DatabaseSync` 不运行在 Electron 主线程。主进程持有受控查询入口，renderer 不接受 SQL 或任意磁盘路径。

推荐深模块 `Catalog` 隐藏 SQL、批次、schema 迁移、查询分页和索引恢复；`FolderRules` 隐藏所有模板落位细节。不要先搭建插件化数据库后端或通用搜索框架。

### 数据模型

- `libraries`：libraryId、volumeId、相对卷根目录、当前挂载点、照片/视频角色、online、当前规则版本、索引状态与 revision。
- `files`：fileId、libraryId、真实 relativePath/parentPath/name、size、mtimeNs、ctimeNs、ino（均保留精确整数文本）、mediaKind、extension、familyId、伴随关系、metadataStatus、扫描代次。
- `capture`：fileId、拍摄时间/本地日历、make/camera/lens 的原文与规范键、focalLengthMm、fNumber、exposureSeconds、ISO、metadataVersion。
- `placement`：fileId、actualRelativePath、expectedRoute（根角色 + 路径）、rulesScope、状态、原因、检查时间。有效路由上下文与原始 EXIF 分开保存：家族继承/修改日期回退不能变成照片的原始拍摄参数。
- `scan_runs`：runId、libraryId、scope（整库或明确子树）、起止/状态/覆盖率、generation、起始 catalog mutation revision。
- `tombstones`：libraryId、旧路径/fileId、mutation revision；防止旧扫描把刚移走或移除的文件重新插回。相关旧扫描全部结束后才清理对应墓碑。

图库身份以卷身份 + 卷内根目录为基础，挂载点变化不变成新图库；相同挂载点换盘必须是另一个库。没有可信卷身份则降级为当前连接的临时身份并说明，不能把旧盘索引绑定给新盘。根目录改名需要显式重绑定或重新索引，不猜测继承。

fileId 是图库内记录身份，不是内容哈希：RAW/JPEG 和两份备份各有条目；伴随文件可折叠展示但不默认把 RAW/JPEG 合并为一张。主媒体计数不含 XMP 等伴随文件，文件详情可展开它们。同名不同路径保留不同记录。仅对本应用已确认的移动保留 fileId，外部重命名不靠不可靠 inode 猜身份。

初始索引：唯一 `(libraryId,relativePath)`；`(libraryId,parentPath,nameSortKey,fileId)`；各分类 `(libraryId,field,fileId)`；拍摄日历复合索引；`(libraryId,rulesScope,placementStatus,fileId)`。按真实查询的 EXPLAIN QUERY PLAN 和基准调整，不枚举所有字段组合。名称第一版用有界筛选查询；若大库 contains 搜索过慢，再单独论证 FTS，不能承诺 B-tree 加速任意子串。

分页以排序值 + fileId 为稳定 cursor，并绑定查询条件 hash / revision；revision 变化要求重新分页，不混用旧页和新统计。类别高基数也分页，不一次返回所有名称、ISO 或焦距值。

## 自动建索引与一致性

1. **扫描发现**：枚举新增路径建立 pending 行；随既有 EXIF 读取批量写入归一值。不在卡/相机上写索引。非图库来源的扫描结果留在当前扫描/元数据缓存，不能提前成为目标库文件。
2. **导入**：规划读取的元数据暂存；只有 `onFileOutcome` 确认的实际目标被加入目标库。published/existing/routed 和每块目标分别处理；失败、取消、尚未发布的计划不计入图库。复制关闭回读校验时保留原有验证等级，不伪称已内容验证。
3. **整理/撤销/恢复/移除重复**：根据已完成的移动更新路径及关系；恢复原件区退出正常浏览范围；undo 后重新进入。不能只接“正常整理结束”而漏掉恢复和部分成功。
4. **索引损坏或更新失败**：文件操作真实结果优先；标记图库索引待修复并安排空闲重扫。进程内用有界批次/背压；积压上限到达则标 dirty，避免无限内存。索引错误不能回滚或重复复制照片，也不导致整个已成功导入显示失败。
5. **重开/连接/外部修改**：先显示上次快照和时间，空闲时只读刷新已纳管图库。基于 stat 判断 EXIF 是否要重读；目录缓存只能复用名称枚举，不能据“名称未变”认定文件内容未变。恢复连接后的 dev/ino 可变，须重新验证，内容哈希不是分类扫描前置。
6. **完整性**：只有成功完成的指定 scope 扫描才能将该 scope 未见的旧记录标 missing；停止、出错、拔盘和局部扫描不能删除整库条目。扫描起始 revision 之后由导入/移动写入的行受保护；移动旧路径与移除记录保留墓碑，旧扫描不能复活它们，也不能覆盖新路径或状态。scope 存在读取失败则对应子树不做“未见即缺失”的收尾。
7. **离线**：展示缓存类别、文件名与已有缓存缩略图，标注离线/上次索引时间；禁用打开原文件、实时 EXIF 与整理。重新连接后先核对卷身份。

用户首次进入旧图库时启动可取消的索引任务，先有文件/日期/格式信息，再逐步补齐 EXIF；显示已发现、已读和失败数量。新增扫描与补扫服从现有 CPU/内存/磁盘限额和导入优先级，磁盘忙时暂停后台补扫，不开启全盘常驻监听器。

## 自定义目录适配与未整理提醒

提取并共享现有 `planOnce()` 的**完整路由与落位判断阶段**，内部复用 `folder()` 的路径构造；仅抽出 `folder()` 不足以保证一致。预览、导入规划、`findMisplaced` 与索引检查共用该阶段，包含模板静态目录、不同日期 token、camera-first、mediaLayout、独立视频模板/根、已编辑目录、未知文件策略、家族/Live Photo/GoPro 分段继承以及现有冲突命名和特殊目录政策。共享判断不包含复制、内容校验或冲突文件的实际发布。

**分类维度与磁盘模板独立**：`旅行/{camera}/{year}/{monthName}` 的照片仍可按镜头和 ISO 分类。实际目录模式展示真实嵌套；无法由 `parseTemplate()` 还原成简单 builder 时照样使用已验证的原始模板。第一版不自动扩展物理目录模板为 `{lens}`、`{iso}`，这不是支持 EXIF 查询的前置条件。

状态模型：

- `inPlace`：符合当前规则，含当前政策接受的冲突命名与合法特殊目录。
- `misplaced`：有足够元数据并完成规则比较，路径不符；保留当前路径、建议路径和原因。
- `unclassifiable`：应用当前家族继承和回退政策后，仍无法确定目标或按 keep 政策刻意保留；独立统计与原因，不直接称未整理。缺 EXIF 并不必然归此状态：folder/fileDate 等政策可能给出有效目标，此时照常比较路径。
- `unchecked`：尚未检查或规则变化后失效；待后台重新评估。

范围之外、Drive backups、应用记录、恢复原件、staging 等不进入未整理统计。已编辑、Unknown files、Problem files、Conflicts 按现有政策处理，不能因为路径与普通模板不同就误报。

每次扫描/导入/整理复用所得数据更新状态。修改规则时只使 placement 失效，EXIF 索引继续可用；无需重新读取照片字节即可重算已知项目。库内外部变动由下次空闲刷新发现，不能承诺未扫描前实时感知。

提醒展示「已检查 8,000 / 10,000，其中 126 个待整理」，未完整检查时不能显示全库“已整理完毕”。部分结果有 badge，并附覆盖率；无变化不反复弹窗。用户点击可筛出待整理文件，查看原因，再进入现有整理 review；真正移动必须使用重新验证的正式计划和原有 Apply 流程。

## 可验收目标（拟定，尚未测量）

- 10 万主媒体的合成库，固定本机 SSD、硬件与版本，预热后常见组合过滤/分栏第一页 p95 ≤200 ms，冷启动首次结果 ≤1 s；1 百万条作扩展压力记录，不先承诺同一指标。
- 默认每页 200、最大 500 条；EXIF 与全库条目不进入普通状态广播；renderer 活动 DOM 行数 ≤500。主进程不执行同步 SQL。
- 交互不触发新一轮 EXIF；未变文件的后续索引扫描无需重读 EXIF；不为索引额外全文件 SHA。
- 数值边界、快门倒数、未知值、RAW/JPEG/XMP、视频、双目标和自定义目录的计数正确。
- 中断扫描不丢旧条目；部分导入只显示真实完成项目；移动、恢复、undo、移除重复后查询一致。
- 索引失败可重建，导入校验与恢复数据行为不受影响。

## 用户追加确认：自由层级与严格只读（2026-10-28）

此节覆盖早先较窄的“调整分类顺序”描述。用户可构造任意长度、任意排列组合的虚拟浏览层级；文件叶节点永远位于最后。支持仅一个维度：光圈值 → 图片；也支持光圈值 → 自定义日期 → 自定义格式 → 相机 → 图片。没有强制的日期/相机中间层，可重复添加同一字段，重复条件按既有 AND 规则求交。

- 提供 block 素材区：日期、名称、格式、相机、镜头、焦距、光圈、快门、ISO。可拖入路径、拖动重排、移除；同时提供键盘“添加/前移/后移/移除”等价操作。每个实例有独立 ID，不能以 field 充当唯一 ID。
- 日期 block 可选年/月/日粒度及展示格式（月分组默认含年，不能把不同年的同一月混合）；名称可首字符/具体名称；格式可具体扩展名或媒体大类；数值 block 可具体值/范围并编辑分桶边界。展示日期格式只允许安全的日期 token 与字面分隔符，不执行表达式。
- 预设包括各单维度入口及“日期→相机→格式”“相机→镜头→焦距”“光圈→日期→格式→相机”；侧栏可直接打开。支持自定义预设命名、保存、重命名、删除并跨重启恢复；默认预设可恢复。切换预设应用完整 block 配置并清理不兼容的选择。
- 实际文件夹模式保持真实目录语义；虚拟 block 只在分类模式解释。
- **严格只读媒体约束**：本功能不修改实际文件格式、编码、内容、EXIF、名称、目录，不创建磁盘上的分类文件夹，不更改 Preferences.template/mediaLayout/videoTemplate/unknownRules 等整理设置。SQLite、缩略图和浏览配置只写本机应用数据。虚拟路径与物理目录模板分开持久化。
- 待整理提醒依据原有整理规则，虚拟层级编辑不使 rulesScope 改变。浏览器不执行移动/整理/删除，仅可跳转到独立现有整理工具，由用户在该工具发起正式 review/Apply。
- 验收新增：拖拽/键盘构造上述两种路径，重复 block、任意重排/移除、配置保存/重启、预设侧栏切换、独立日期/格式设置；比较源文件字节、stat、路径与整理偏好前后未变。

重复字段的候选计数也须遵循层级：查询携带 block 实例 ID，facet 仅排除本实例自己的选择，保留上游同字段的约束。例如焦距范围 24–70 → 焦距具体值，第二列只能列出该范围内的值。

## 用户追加：摄影标准分组与术语

ISO、快门和光圈的默认分组/标签采用摄影常用标准档位，不显示无单位的小数区间。光圈使用 f/1、f/1.4、f/2、f/2.8、f/4、f/5.6、f/8、f/11、f/16、f/22、f/32；ISO 使用100、200、400、800、1600、3200、6400、12800及更高档；快门使用1/8000、1/4000、1/2000、1/1000、1/500、1/250、1/125、1/60、1/30、1/15、1/8、1/4、1/2、1、2、4、8、15、30秒。分组沿标准档位边界，标签保持秒/倒数秒、f数及ISO，区分更快/更慢、更大/更小光圈的数字方向。中间实测值（f/1.8、ISO125、1/160等）保留原数值可选；不静默四舍五入成另一真实曝光值。已有用户自定义区间和保存预设不能被新默认值覆盖。
