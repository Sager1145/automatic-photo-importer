# Library browser

Open **Library browser** in the sidebar and choose a configured photo or video library. **Refresh index** reads the library into a local, rebuildable catalog. The status shows indexing progress, known details and placement coverage. An offline library keeps its indexed details; reconnect its drive to load previews or refresh it.

The page follows Lightroom Classic's Library module, top to bottom. The source row holds the library picker, the folder button that adds any other folder to browse (a browsed folder also gets a button to stop browsing it), Back and Forward, the index status and **Refresh index**. Under it is the filter bar: **Categories** or **Real folders**, **Search names**, **Placement** (not for a browsed folder), the view preset menu (built-in views and your saved ones; **Custom view** when the columns match none), **Columns** (opens the column editor described below) and **Clear all**. The preset menu and **Columns** work in Categories only. Below are the category columns. Each column's header menu changes the field it shows, adds a column after it or removes it, and for a date column turns Year, Month and Day on or off; the **+** after the last column adds one. Drag the handle under the columns to set their height (double-click restores the default split: the columns take about 45% of the room below the bars, the results the rest). The results fill the rest: **Files** with its count, a check box, **Sort**, **RAW + JPEG** and **Drag to Lightroom** in its header, then the file list, with the picked file's preview beside it. The Files list is not a column; it always follows the columns. Until something is chosen, a one-line hint under the filter bar says how: in Categories, click a row to show it for now and tick its box to keep it chosen; in Real folders, click a folder to open it, its subfolders in the next column and its files below.

In **Categories** every row has a small check box. The check box keeps the row chosen: click it to check the row, click it again to uncheck it. Clicking the row itself only shows it for now (a temporary pick): clicking another row moves the pick, and clicking the picked row again drops it. A column filters the next ones by its checked rows plus the pick, so one click is enough to look at a month, and checking keeps rows while you look at others. Several rows in one column are alternatives: the next columns show everything they hold together (two checked months show the cameras of both). Ctrl/Command-click and Space check or uncheck a row; Shift-click checks the rows from the keyboard cursor (the row you last used) to the clicked one. **Missing details** can be chosen together with values. Different columns narrow the result together. A column can filter by at most 500 values (ranges count as values), however they are checked: a check box or a click that would pass the limit is refused, a Shift range or Select all stops there, and the column says “A column can filter by at most 500 values.” In a date tree the arrow beside a year or month opens it; checking a year covers its months and days, and a year or month with only some of its rows checked shows a half-set check box, and one that shows checked because every month or day under it is checked unchecks with one click (those rows and anything under them are cleared). **Real folders** columns have no check boxes: they select one folder at a time (a click opens it in the next column), since each column lists the children of one folder.

When something is chosen, a bar under the filter bar shows the selection as a path in column order, each part with its values in column units and, when there are several, their number: “2026 › 202609, 202610 (2) › NIKON Z f”. Long lists show the first three and how many more. Checked files add “N files selected”. Clicking a part clears that column's checks and pick and the columns after it. **Clear all** in the filter bar clears the column choices, the opened folders, the placement filter, the checked files, the preview and the name search; it is disabled only when nothing is chosen and the name search is empty. Each column header also shows how many of its rows are chosen (checked or picked) before the column's total, for example “3/12”; both numbers count the same rows, **Missing details** included when the column shows it.

Each category column's header has one check box. Unchecked, it checks every row of the column; when anything in the column is checked (the box is then set or half set), it clears the column's checks and its pick. It replaces the former Select all and Deselect all buttons. Checking every row reads the column's remaining pages first, so it covers rows not yet scrolled to; it stops at the 500-value limit, and for a plain list of more than 500 values (not a date tree or numeric ranges) the box is unavailable (“Too many values to select at once”); clearing is always available. A click that would take the column past 500 values with its checks is refused, and its row is not shown picked. A date tree's header counts its top rows, each year and **Missing details** when that row is shown (“1/2”: something is chosen in one of two top rows), and its box is set when every year is fully checked and, when a Missing details row is shown, that too, whatever is expanded. Real folders columns have none.

**Files** works alike. A click on a file previews it, and the preview opens beside the list; clicking the previewed file again closes it. The previewed file counts as chosen for **Drag to Lightroom**. The check box of a file chooses it without moving the preview. The check box in the Files header checks every file the columns show (including ones not loaded yet) and keeps the preview, or, when any file is checked, clears the checks and closes the preview; after checking all, unchecking single files keeps the rest. Other changes close the preview too: **Sort** drops the previewed file but keeps the checked files; **RAW + JPEG**, a **Search names** edit, a change in any column, the placement filter, the library or the mode, and **Clear all** drop the previewed file and the checked files both. The count in the header shows the files chosen before the total, for example “5/1,204”.

Keyboard, in a category column or in Files: Up, Down, Home and End move the pick; Shift with an arrow, Home or End also checks the rows from the cursor to the row it reaches; Ctrl/Command with an arrow only moves the cursor; Space checks or unchecks the row at the cursor; Enter picks it. Esc closes an open preview first; with none open, it clears the column's checks and pick (in Files, the checked files). Left and Right move to the previous or next column; Right from the last column moves to the Files list and Left there comes back; in a date tree, Right on a closed year or month opens it and Left on an open one closes it instead. In a Real folders column the arrow keys and Enter open the folder.

**Drag to Lightroom** ends the results header, like LRTimelapse's drag button. Drag it onto Lightroom Classic's Library grid or its Import window to import the chosen files: the checked files plus the previewed one, or every file shown when there are neither. Its label shows which and how many (“3 selected” or “All 120”). Any app that accepts dropped files takes it too (Finder, File Explorer, Photoshop). The drag carries, for each photo, the RAW shown with a JPEG or HEIF (**RAW + JPEG**) and every companion the catalog recorded for it, such as an `.xmp` sidecar; Lightroom reads the `.xmp` beside a RAW and ignores companions it does not import. The main process resolves every file through the catalog (each must still be inside the library and on its drive) as soon as the pointer reaches the handle, then starts the system drag with Electron's `startDrag`. Files that cannot be read now are left out and counted under the handle. A drag holds at most 10,000 files, and is refused rather than cut short beyond that; the drive must be connected.

**RAW + JPEG** (in the results header, on by default) shows a RAW file and the JPEG or HEIF taken with it as one photo. **Columns** in the filter bar opens the column editor, headed **Virtual hierarchy** and closed until opened; its path shows the columns and always ends in Files, the list in the results pane. Use the field palette to add Date, Name, Format, Camera, Lens, Focal length, Aperture, Shutter speed or ISO. Drag a field into the path, drag existing blocks to reorder, or use a field's **+** (adds it as the last column), **Move earlier**, **Move later** and **Remove block** with the keyboard. Repeated fields have independent selections. A column's header menu does the same for a single column without opening the editor.

Select a path block to configure it. Dates have Year, Month and Day levels: two or more show as a tree, one as a flat list with display tokens (`YYYY`, `MM`, `DD`). Names group by first character or full name; formats group by extension or media kind. New Aperture, Shutter speed and ISO blocks start with standard photographic stop buckets. Labels use f-numbers, ISO values and shutter fractions such as `1/125 s`. Switch **Numeric grouping** to **Exact values** to see intermediate values recorded by the camera, or edit **Bucket boundaries** and enter a custom range. Shutter boundaries and ranges accept fractions such as `1/125`; ISO inputs accept `ISO 400`. Existing saved views retain their grouping choices.

New **Aperture**, **ISO** and **Shutter speed** blocks, including built-in presets, start with standard-stop ranges. Aperture boundaries run from f/1 to f/32; ISO uses doubling steps from ISO 50 to ISO 102400; shutter boundaries use nominal photographic durations from 1/8000 s to 30 s, including exact fractions such as 1/125 s and 1/60 s. Range labels show their edges explicitly, for example **≥ f/2.8 – < f/4** or **≥ 1/125 s – < 1/60 s**. Empty ranges are hidden unless selected. Shared boundaries belong to the following range, so no capture is counted twice.

Choose **Exact values** to see the recorded values, including intermediate settings such as f/1.8, ISO 125 and 1/160 s. Values are never rounded or reassigned to a nominal stop. The boundary editor accepts and displays photographic labels such as `f/2.8`, `ISO 400`, `1/125 s` and `2 s`. Previously saved views and custom preset boundaries keep their existing settings; adding a new block or choosing a built-in preset uses the new defaults.

The column editor (**Columns** in the filter bar) holds the fields, the levels and the presets, single-field and multi-field views. Enter a name and choose **Save current view** to save the entire hierarchy and its options. Rename or delete a custom preset using its adjacent controls. The view preset menu in the filter bar picks the same presets. Presets and the current view persist locally when the app restarts. **Restore default view** restores the default columns (Date › Camera › Format) only: saved presets and the layout settings (column width and height, preview width, Larger preview, hidden bars and columns) stay.

**Real folders** follows existing directories: each column lists the subfolders of one folder and a click opens one in the next column. The view preset menu and **Columns** are off. Clicking a file opens its thumbnail and indexed details beside the list; **Full EXIF** reads further tags on request and **Show in file manager** reveals the file. Every detail has an icon; Full EXIF shows the same labelled categories as the Duplicates page (exposure, camera and lens, date, location, image, maker notes, file), each field with its icon, and keeps every raw tag, with an icon for its group, under **All tags**. Esc closes the preview. The column separator adjusts column width.

The preview can take more room. Drag the divider between the file list and the preview, or focus it and use Left (wider) and Right; double-click restores the default width. **Larger preview** in the preview's header gives the preview everything but the list's minimum width (220 px); dragging the divider turns it off. The picture scales into its panel without being enlarged and the details scroll under it. A preview whose picture box has the room for it (its longer side times the device pixel ratio is above 900, so also on a HiDPI screen) asks for a 1600-pixel picture instead of the usual 900, but only for a picture the system decoded (an embedded camera preview is the same at every size) and only after the file has stayed selected about a quarter of a second, so stepping through files with the arrow keys asks for nothing more; a preview that has the room from the start asks once for the large picture and never for the normal one first. `thumbnail(path, size)` accepts only those two sizes, each cached on its own, made by `sips` on macOS, the shell thumbnailer on Windows and Electron's decoder on Linux; a picture is never enlarged beyond its own size on any system, and originals never reach the page. Two small buttons after **RAW + JPEG** in the results header hide or show the bars above (source row, filter bar and selection path, with the column editor) and the category columns with their height handle, so the results fill the window. Hidden columns keep filtering: while the bars or the columns are hidden and something filters, the header shows “Filters: N” (one for each column with a choice, the opened folder path, the placement filter and the name search), each named in its tooltip, with a **Clear filters** button that clears the column choices, folders, placement and name search but keeps the files you checked and the preview. Two exceptions: a check on all files is dropped (it would now cover more files), and in Real folders with a folder open the checked files and the preview go too, since they belonged to that folder. The preview width, Larger preview and both hidden regions are saved with the view (`previewWidth`, `previewLarge`, `hideBars`, `hideColumns` in the browser configuration).

Browsing and hierarchy editing do not change media bytes, formats, EXIF, names or paths, create classification folders, or change organization preferences. **Open organization tool** only navigates to the separate organization page. Review and apply any physical reorganization there.

The SQLite catalog and thumbnail/browser caches live in local application data. Filtered columns and file lists read their matches from indexes that hold the filtered fields, so choosing several values or combining columns stays fast in libraries of 100,000 files; the first start after an update that changes these indexes rebuilds them once (about five seconds for 100,000 files). Indexing a large existing library takes time; results show current coverage. Removing or corrupting a catalog requires reindexing, rather than changing originals.
